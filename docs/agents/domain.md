# Domain docs

The repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before exploring an area, read the root glossary and relevant ADRs when they exist. If they do not exist, proceed without flagging their absence; the domain-modeling skill creates them when terms or decisions are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests. If work conflicts with an ADR, name the ADR and explain the conflict.
